# @hazejs/core

## 0.4.0

### Minor Changes

- [`a7d7a1b`](https://github.com/penna-org/haze/commit/a7d7a1b2c351570511883fe28cc743e2b86f5c0f) Thanks [@aibayanyu20](https://github.com/aibayanyu20)! - `ctx.sse(source, options?)` returns a Server-Sent Events response. The source is an async iterable (one event per item, closes when it ends) or a function that keeps the stream open until `stream.close()`. It sends a `: ping` heartbeat every 15 seconds, closes and runs `stream.onClose()` hooks when the client disconnects, logs and closes on source errors, and sets `cache-control: no-cache, no-transform` and `x-accel-buffering: no`. `eventStream()` and `encodeSseEvent()` are exported for use outside a request. Broadcasting's `/broadcasting/sse` and the dev dashboard stream now use it, and `cacheResponse` no longer buffers `text/event-stream` responses.

- [`bd81767`](https://github.com/penna-org/haze/commit/bd817672b975e2475a7644214396915d5f247f9b) Thanks [@aibayanyu20](https://github.com/aibayanyu20)! - Queue enhancements that work on every driver:

  - **Batches.** `Queue.batch([...]).name().allowFailures().then().catch().finally().dispatch()` tracks progress (`total`, `pending`, `processed`, `failed`, `progress`, `finished`, `cancelled`). It supports `batch.cancel()`, `batch.add()`, `Queue.findBatch(id)` and `job.batch()`. State lives in a cache store (`config/queue.ts` `batches: { store, ttl }`), and `then` / `finally` run exactly once.
  - **Unique jobs.** `defineJob({ unique: { key, for, until } })` takes a cache lock on dispatch and skips duplicates. `Job.with(p).dispatch()` returns `{ id, skipped }`.
  - **Job middleware.** `defineJob({ middleware: [...] })` and the global `config/queue.ts` `middleware` wrap jobs. Built in: `rateLimited`, `withoutOverlapping`, `throttlesExceptions` and `skipIf`. Use `job.release(delay)` to put a job back without counting an attempt.
  - **Callbacks.** Chain and batch callbacks are job references (`Job.with(payload)`) or, on `sync` / `memory` connections, functions.

  `@hazejs/orm` adds the `database` queue driver (`driver: 'database'`, registered by `databaseProvider()`). It claims jobs with `FOR UPDATE SKIP LOCKED` on PostgreSQL and MySQL 8, and with an atomic `UPDATE … RETURNING` on SQLite, libsql, Turso and D1. It also supports delays, retries, release of stale reservations and the `failed_jobs` table.
  
  `@hazejs/cli` adds `haze make:queue-tables`, which writes the drizzle schema for the `jobs` and `failed_jobs` tables and runs `db:generate`.

Jobs accept `defineJob({ afterCommit: true })`, `dispatch(payload, { afterCommit })` and `Job.with(payload).afterCommit()`; a deferred `Job.with().dispatch()` resolves to `{ id, skipped: false, deferred: true }`. Registering two different jobs or two different listeners under the same name (for example `app/job/Cleanup.ts` and `app/job/admin/Cleanup.ts`, or a module's file and a project file) now fails at boot with an error naming both sources instead of silently replacing one. A successful job logs a debug line with its name, duration and attempt, and an `s.job()` task logs "Scheduled job dispatched to the queue". `queue.runInServer` no longer starts a worker for a `sync` connection (it logs a warning) or for a `memory` connection that already consumes the `default` queue, and a worker that fails to start is logged instead of causing an unhandled rejection; `QueueManager.work()` / `haze queue:work` refuse the `sync` connection with a clear error. A unique job that takes its lock in a `memory` cache store while its connection is consumed by another process logs a one-time warning.

  Types: Redis connection names are generated into a separate `GeneratedRedisConnections` interface, and generated config and policy imports keep their file extension so they resolve under `moduleResolution: "nodenext"` in ESM projects; `connection: 'default'` in `config/cache.ts` no longer fails with "Type 'string' is not assignable to type 'undefined'". `defineCacheConfig` accepts stores added with a conditional spread (new `CacheConfigInput` type).

### Patch Changes

- [`a5fd5cf`](https://github.com/penna-org/haze/commit/a5fd5cfa6753af24f147959b29ef6af4a31c99c4) Thanks [@aibayanyu20](https://github.com/aibayanyu20)! - Gate denials for signed-in users throw `AuthorizationException`, a `ForbiddenException` subclass carrying `abilities` (the denied ability, or every candidate for `authorizeAny`) and `reason` (the `deny()` message), so exception handlers can name the missing permission or localize the message. Status, code and default message are unchanged.
  
  `ctx.route` exposes the matched route — `method`, the `path` pattern, `name` and the `meta` set with `.meta()` — so route middleware such as audit logs can read what the route declared.
  
  Middleware passed as a function or class is listed as `name()` (`route:list`, `RouteRecord.middleware`), so a function that happens to be called `guest` or `auth` is no longer mistaken for that alias — previously OpenAPI added a `403` / `401` response for it.
  
  `app.onBooted(callback)` runs a callback after every provider has booted (immediately once the app is booted), so module providers — which boot before the app's — can wait for resources an app provider prepares, such as an open database connection.

- [`a5fd5cf`](https://github.com/penna-org/haze/commit/a5fd5cfa6753af24f147959b29ef6af4a31c99c4) Thanks [@aibayanyu20](https://github.com/aibayanyu20)! - ORM fixes and additions found while porting a production backend onto `@hazejs/orm`.
  
  Querying: `where()`, `orWhere()` / `whereOr()` and `whereNot()` (and static `Model.where()`) accept `undefined` and ignore it, so drizzle's `and()` / `or()` results can be passed directly. New `whenDefined(value, callback, otherwise?)` applies the callback unless the value is `undefined` / `null` (`when()` still also skips `false` and `''`). `order(sqlExpression, 'asc' | 'desc')` takes a direction. `lock()` accepts `'no key update'` and `'key share'` (PostgreSQL) and a second `{ skipLocked, noWait }` argument (PostgreSQL / MySQL 8); unsupported combinations throw a `DatabaseError`. `exists()` now runs `select 1 … limit 1` instead of reading a full row. `paginate()` runs the count and the page query in parallel outside transactions; inside a transaction it runs them in sequence and skips the page query when the total is `0`.
  
  Types: model queries are now fully typed — `TableOf<M>` no longer intersects with `Table`, which had widened every column key to `string` and every value to `any` (`User.where('typo', 1)` now fails to compile; `User.query().column('name')` is `string[]`). `value()` and `column()` also accept `field()` aliases, typed and at runtime. `leftJoin()` / `rightJoin()` / `fullJoin()` return the builder marked with the joined tables (`JoinMarker`), so a following `field({ ... })` types the columns of tables that may be missing as `T | null`; `field({ log: logs, userName: users.name })` selects a whole table as a nested row object (`Row | null` when outer-joined). `model.getData()` returns the table's row type. Insert values (`insert()`, `upsert()`, `Model.create()`) may be drizzle `SQL` expressions (`InsertValues<T>`).
  
  Writes: `update(values, { returning: true })` returns the updated rows (PostgreSQL / SQLite). `update()` drops keys whose value is `undefined` and throws `DatabaseError('update() called without data')` when nothing remains, instead of drizzle's "No values to set". `insert(values, { returning: false })` returns the inserted count without reading rows back. `upsert()` accepts `update` as `{ column: value | SQL }`, a `where` condition (`ON CONFLICT … DO UPDATE … WHERE`) and `returning: true` (PostgreSQL / SQLite; MySQL throws). `selectInsert(table, { ignore: true })` skips duplicate rows. `toSQL('insert', values)`, `toSQL('update', values)` and `toSQL('delete', target?)` preview write statements without running them. New static `Model.updateById(id | ids, values)` runs a single `UPDATE` by primary key without loading the model: it sets `updatedAt`, skips read-only fields, increments the optimistic-lock version and fires no events.
  
  Behaviour changes: `UniqueConstraintException` now renders `code: 'unique_violation'` (previously `409`; the HTTP status is still 409) and carries `constraint`, `table`, `columns` and `detail` parsed from the driver error (new `uniqueViolationOf()` helper and `UniqueViolation` type); its default message is translated through the new `http.unique_violation` key in `@hazejs/core`'s framework messages. With `optimLock`, a new model no longer writes `0` into the version column when the column has a database default — the default (for example `default(1)`) is used. Model queries' `delete()` is now implemented through an overridable statement builder; behaviour is unchanged.

- [`15e802d`](https://github.com/penna-org/haze/commit/15e802d5f341a9928720189ed49a9cba8ff168f2) Thanks [@aibayanyu20](https://github.com/aibayanyu20)! - The request context and the telemetry scope now live on `globalThis`, shared by every copy of `@hazejs/core` in the process. - [`a5fd5cf`](https://github.com/penna-org/haze/commit/a5fd5cfa6753af24f147959b29ef6af4a31c99c4) Thanks [@aibayanyu20](https://github.com/aibayanyu20)! - `app.serve()` no longer hangs on `SIGTERM` / `SIGINT` while WebSockets, SSE streams or keep-alive connections are open: after waiting for in-flight requests up to `app.shutdownTimeout` (default 10 seconds) it closes the remaining connections, disposes the application and exits.
