'@hazejs/core': patch

ORM fixes and additions found while porting a production backend onto `@hazejs/orm`.

Querying: `where()`, `orWhere()` / `whereOr()` and `whereNot()` (and static `Model.where()`) accept `undefined` and ignore it, so drizzle's `and()` / `or()` results can be passed directly. New `whenDefined(value, callback, otherwise?)` applies the callback unless the value is `undefined` / `null` (`when()` still also skips `false` and `''`). `order(sqlExpression, 'asc' | 'desc')` takes a direction. `lock()` accepts `'no key update'` and `'key share'` (PostgreSQL) and a second `{ skipLocked, noWait }` argument (PostgreSQL / MySQL 8); unsupported combinations throw a `DatabaseError`. `exists()` now runs `select 1 … limit 1` instead of reading a full row. `paginate()` runs the count and the page query in parallel outside transactions; inside a transaction it runs them in sequence and skips the page query when the total is `0`.

Types: model queries are now fully typed — `TableOf<M>` no longer intersects with `Table`, which had widened every column key to `string` and every value to `any` (`User.where('typo', 1)` now fails to compile; `User.query().column('name')` is `string[]`). `value()` and `column()` also accept `field()` aliases, typed and at runtime. `leftJoin()` / `rightJoin()` / `fullJoin()` return the builder marked with the joined tables (`JoinMarker`), so a following `field({ ... })` types the columns of tables that may be missing as `T | null`; `field({ log: logs, userName: users.name })` selects a whole table as a nested row object (`Row | null` when outer-joined). `model.getData()` returns the table's row type. Insert values (`insert()`, `upsert()`, `Model.create()`) may be drizzle `SQL` expressions (`InsertValues<T>`).

Writes: `update(values, { returning: true })` returns the updated rows (PostgreSQL / SQLite). `update()` drops keys whose value is `undefined` and throws `DatabaseError('update() called without data')` when nothing remains, instead of drizzle's "No values to set". `insert(values, { returning: false })` returns the inserted count without reading rows back. `upsert()` accepts `update` as `{ column: value | SQL }`, a `where` condition (`ON CONFLICT … DO UPDATE … WHERE`) and `returning: true` (PostgreSQL / SQLite; MySQL throws). `selectInsert(table, { ignore: true })` skips duplicate rows. `toSQL('insert', values)`, `toSQL('update', values)` and `toSQL('delete', target?)` preview write statements without running them. New static `Model.updateById(id | ids, values)` runs a single `UPDATE` by primary key without loading the model: it sets `updatedAt`, skips read-only fields, increments the optimistic-lock version and fires no events.

Behaviour changes: `UniqueConstraintException` now renders `code: 'unique_violation'` (previously `409`; the HTTP status is still 409) and carries `constraint`, `table`, `columns` and `detail` parsed from the driver error (new `uniqueViolationOf()` helper and `UniqueViolation` type); its default message is translated through the new `http.unique_violation` key in `@hazejs/core`'s framework messages. With `optimLock`, a new model no longer writes `0` into the version column when the column has a database default — the default (for example `default(1)`) is used. Model queries' `delete()` is now implemented through an overridable statement builder; behaviour is unchanged.
