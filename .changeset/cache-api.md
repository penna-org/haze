Richer cache API in the style of ThinkPHP. Repositories and the `Cache` facade add `delete`, `clear`, `inc` / `dec`, `getMultiple` / `setMultiple` / `deleteMany` / `deleteMultiple` next to the existing names; `push(key, value, ttl?)` appends to array items (atomic on memory, Redis and Upstash through a Lua script); `ttl(key)` and `touch(key, ttl)` / `expire` read and change the remaining time (KV reads it from metadata); `handler()` returns the underlying client (the shared ioredis connection, the Upstash client, the memory `Map` or the KV binding). Tags work on every driver through per-tag versions (`Cache.tag('user')`, `Cache.tag(['user', 'post']).clear()`), and Redis also indexes tagged keys so `clear()` frees memory. Stores whose driver is `redis` return a `RedisCacheRepository` with typed hash, list, set and sorted-set handles (prefixed, serialized per element, with TTLs); memory stores emulate them for tests. `Cache.store('redis')` is typed per driver from the generated `config/cache.ts` types, with `Cache.redis()` and `isRedisCache()`. New `cache()` helper: `cache(key)`, `cache(key, value, ttl?)`, `cache(key, null)`, `cache()`. Values are now serialized as JSON that restores `Date`, `BigInt`, `Map`, `Set` and nested `undefined` (`serializer: 'typed'`, the default, still valid JSON and backward compatible with plain JSON values); set `serializer: 'json'` globally or per store to keep returning dates and BigInts as strings, or pass a custom `{ serialize, deserialize }`.
