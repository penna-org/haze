Authentication and authorization hooks for apps with stateful sessions and data-driven permissions. JWT guards accept `resolveUser(payload, ctx)` to resolve the user from the verified claims and the request (check a session id on every request, read an organisation header); `HttpException`s it throws become the response unchanged. `rejectClaims` refuses tokens carrying given claims (password-reset tickets signed with the same secret), `expiresIn` may be a function evaluated per login, and `jwt().login(user, claims, { expiresIn })` overrides it per token. The `auth` middleware answers `401` with `code: 'unauthenticated'` (no credentials) or `'token_invalid'` (expired, tampered, rejected), and `auth:optional` / `auth:<guard>,optional` lets requests through as guests. Guards expose `failure`. `gate.fallback((user, ability) => …)` decides abilities that have no definition (permission codes stored with roles), `ctx.authorizeAny([...])` / `gate.authorizeAny()` and `can:a|b` pass when any ability is granted. `@hazejs/socket.io`'s `authenticate({ headers })` passes handshake `auth` fields to the guard as request headers, and rejected handshakes carry `error.data = { status, code }` with the same codes as the HTTP API (previously `{ code: 401 }`). Backend-only projects can serve a separately built frontend through `config/static.ts` (`dir` may come from an environment variable; relative to the project root), and the docker preset's Dockerfile has a `HEALTHCHECK` on `/health/live`. `ApplicationOptions.configOverrides` (and so `createTestApp({ configOverrides })`) deep-merges configuration over `config/*.ts` before providers register, keeping class instances such as database clients by reference.
