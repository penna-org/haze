ORM connections for existing drizzle codebases. New `node-postgres` driver (`pg`, drizzle's default PostgreSQL driver) next to postgres-js. Connections accept `casing` (`'snake_case'` / `'camelCase'`) for tables whose columns are declared without names — passed to every drizzle instance, used by `upsert()` / `selectInsert()` column lists and forwarded by `haze db:generate` to drizzle-kit; `timezone` to set the PostgreSQL session time zone (`postgres`, `node-postgres`, `pglite`); and `client` to use an existing `PGlite`, `pg.Pool` / `pg.Client` or postgres-js instance that the app never closes (several apps sharing one in-memory database in tests). `Db.connect()` opens a connection eagerly and `Db.drizzleSync()` returns the current drizzle instance (the transaction object inside a transaction) for code that cannot await, such as repositories with a `db` getter. `Db.joinTransaction(tx, fn)` lets a transaction opened by another library through drizzle join the context, so `Db` / `Model` queries inside run in it and nested transactions become savepoints. Several applications in one process (typical in tests) no longer step on each other: inside a request `Db` / models use the manager of the application handling it, closing an application restores the previously active manager, transactions are tracked per manager, and `Db.withManager(manager, fn)` pins code outside requests — including timers and promises created inside — to one application's connections. `resolveSessionSync()`, `joinTransaction()` and `withDatabaseManager()` are exported for custom integrations.
