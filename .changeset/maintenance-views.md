Maintenance mode and server-side TSX views. `haze down [--secret] [--retry] [--refresh] [--status] [--redirect] [--render] [--except] [--message]`, `haze up` and `haze maintenance:status` (in production `node dist/worker.mjs down` / `up` / `maintenance:status`) put the application into maintenance mode: requests get 503 with `Retry-After` — the JSON error envelope (translated with `http.maintenance`) for API clients, a built-in page, a custom view or a redirect for browsers — while health checks, `except` paths, the dev dashboard and browsers holding the signed bypass cookie (from visiting `/<secret>`; the secret is stored hashed) pass. The state lives in the cache store by default (`config/maintenance.ts`, `defineMaintenanceConfig`; an in-process memory store falls back to `storage/framework/down` outside tests) or a local file, is cached in each process for two seconds, and pauses queue workers and the scheduler (`pauseWorkers`). New `Maintenance` facade and `MaintenanceModeEnabled` / `MaintenanceModeDisabled` events. Core now ships a zero-dependency JSX runtime (`@hazejs/core/jsx-runtime`, `@hazejs/core/jsx-dev-runtime`) that renders escaped HTML strings on every runtime, including Workers: async components, `rawHtml()` / `dangerouslySetInnerHTML`, `Doctype`, `class` arrays and objects, `style` objects and typed HTML attributes. `ctx.view(<Home />, { status, headers })`, `ctx.view(Home, props)`, `ctx.view('admin/Dashboard', props)` (files in `app/view`), `view()` and returning a JSX node from a handler render `text/html` without the JSON envelope; `useHttpContext()`, `useView()`, `csrfField()`, `old()` and `flashInput()` help with pages and forms. The Vite plugin compiles backend `.tsx` / `.jsx` files with this runtime in the backend environment only, so React frontends keep their own JSX. New `haze make:view`; the `api` template renders a TSX welcome page at `GET /`, and template tsconfigs enable `jsxImportSource: '@hazejs/core'` for backend files.
